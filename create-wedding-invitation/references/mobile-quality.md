# Mobile invitation quality

## Final materials check

Run this as a finishing step after the last supplied assets and final copy are integrated, before exporting or publishing. If the user adds or replaces material later, repeat the check for affected pages and the overall four-page rhythm.

1. Preview the actual rendered pages with final photos loaded. Review all four screens in sequence, not just a full-page thumbnail or CSS dimensions.
2. Optimize each screen's visual proportions: title hierarchy, photo size and crop, text wrapping, card alignment, spacing and visual center. Keep faces and important details visible; balance generous whitespace against a sparse or crowded result. Use the bundled proportions as a starting point, not a fixed ratio regardless of content.
3. Verify the mobile sizes listed below and a desktop viewport. Check one-screen fit and child bounds without clipping, readable text and usable navigation targets. Keep confirmed facts, selected theme and projector interactions unchanged while adjusting layout.
4. Re-test continuous auto-play, direct dragging and click-to-enlarge, plus address navigation, countdown, optional music and reduced-motion behavior. Check photo lightbox titles and captions against [copywriting-guide.md](copywriting-guide.md#photo-lightbox-copy): no unintentional asset labels or blank descriptions, correct text for the selected image, and readable text on a phone. Check for failed resources. Fix visual problems, reload and inspect again.
5. Report briefly which final-content checks passed and any remaining missing assets or limits. If assets are still missing, call the result a preview, not a completed final-materials check. Export only the checked revision; retain the separate authorization requirements for publishing.

## Layout and interaction guidance

- Default to one section per safe phone viewport. Test 320×568, 375×667, 390×844 and 430×932 with the actual content. Compare each section's height to the viewport AND inspect child bounds; hiding overflow is not a fix. Long confirmed itineraries, unusually long names or enlarged accessibility text may need a different layout or natural scrolling. Do not discard content to force a fit.
- Use height-aware image sizing and card typography: compact phones get tighter spacing; tall phones get larger photos, text and information cards. Do not leave a tiny card floating in a large empty screen, or stretch blank space instead of improving content hierarchy.
- Preserve the approved four-page composition in the project’s existing stylesheet structure; it may be a dedicated `composition.css` or a clearly labeled section in consolidated CSS. On tall phones (at least 740px high), use a restrained cover title and about 41svh cover photo; a roughly 46svh continuous film strip below the gallery heading; an information card around 82svh with aligned fields and a lightly separated countdown; and a roughly 49svh ending photo with a distinct signature gap. These are starting proportions, not fixed requirements for longer content. Small phones retain the compact layout. Preserve theme colors and projector interactions when refining spacing. Verify 417×812 as well as the other mobile sizes; new user photos or longer copy require another visual check.
- Missing photos must not leave an unexplained empty gallery. The template shows clearly labelled neutral gallery placeholders. Replace them with provided photos when available; never use another couple's portraits. Review all four sections again after adding photos.
- Preserve the classic projector interaction when adapting images: a continuously moving, seamless looping film strip with film-edge decoration, direct touch/mouse dragging and click-to-enlarge. Resume about 1.2 seconds after dragging. Do not replace it with discrete full-width slides, arrows, counters or visible playback buttons unless requested. Pause offscreen, in background tabs and while a lightbox is open; respect reduced motion and provide keyboard browsing/pause without adding visible controls. Do not autoplay missing-photo placeholders. Test actual movement and dragging, not merely overflow CSS; dragging must not open the lightbox or block vertical page scrolling. If the user refers to a reference version, inspect its implementation before changing the interaction.
- Keep paper grain independent of decorative ripples. The Chinese-red preset retains paper texture without ripples. Honor theme and texture choices; do not force Chinese red onto every invitation.
- Verify venue addresses against a reliable map listing or hotel source. If sources disagree, disclose the discrepancy and use a map link matching the selected hotel. Keep the user-confirmed banquet hall separate from the street address; do not invent a floor, entrance or precise room pin. Do not copy a previous couple's venue into a new invitation.
- The third section includes a location card; show the external navigation button only for a verified supported URL. The map opens on a deliberate click, not an automatic external embed. Test the rendered link target.
- Remove empty dress-code and itinerary rows together with their spacing. Never synthesize an itinerary merely to repeat the event time. Preserve explicitly confirmed schedule items.
- After corrections, update source JSON and generated config consistently. Update/reload cached assets, then verify the visible page, not just the source files. Regenerate requested exports after approval of the revised preview.

## Whole-page typography and closing signature

- Review typography as a complete page with final photos: title, invitation sentence, names, event details and closing signature should have deliberate hierarchy. Do not judge readability solely by whether content fits inside the viewport.
- Treat the closing names and invitation sign-off as meaningful content, not a tiny decorative caption. On ordinary phone screens, start around 18–20 CSS pixels for a short signature and adjust to actual font, name length and available width; this is guidance rather than a universal fixed size. Keep secondary English labels visually subordinate.
- After changing signature size, inspect the full closing screen at compact and tall phone sizes. Check the gap below the photo, balanced top and bottom space, line wrapping, contrast over paper texture and visibility without zooming. Adjust spacing or photo size if needed instead of shrinking important text just to force one-screen fit.

## Shared-link preview

- Follow the classic template: put the final `og:title`, `og:description`, and `og:image` values directly in the initial HTML. Use the approved cover by default, then the first approved gallery photo or ending photo if needed; let WeChat apply its own link-card layout. Do not create a separate designed share card or image-generation script unless the user explicitly asks for one.
- Before WeChat sharing, `og:image` must contain the image's public absolute HTTPS URL, such as `https://example.com/invitation/assets/photo.jpg`. Do not use a relative path or SVG placeholder. Link-preview crawlers may not run invitation JavaScript, so client-side meta updates are only a secondary fallback.
- After publishing, fetch the actual public HTML and resolved share-image URL. Confirm the HTML contains the final static metadata and the image returns HTTP 200 with an image content type. A local preview or successful source upload alone does not prove that WeChat can access the image.
