# Photo slots

## Selection

- Cover: one strong portrait image, ideally 2:3 or 3:4, with visual breathing room around faces.
- Gallery: 5–12 images. Mix portraits and landscapes, order them as a story, and avoid near-duplicates.
- Ending: one warm image that works behind or above closing copy.
- Share: use the approved cover (the first displayed photo) by default. If there is no cover, use the first approved gallery photo, then the ending photo. Ask for a separate image only if the user wants to choose one or none of these is suitable. Let WeChat format the link preview; create a custom crop or designed card only when the user requests one.

## Processing

- Correct orientation before resizing.
- Use an approximately 1600–2400 px long edge for lightbox images and 900–1400 px for display images when creating custom variants.
- Prefer JPEG around quality 80–86 or WebP around quality 78–84.
- Strip unnecessary metadata when privacy matters, especially GPS metadata.
- Never bundle the user's original camera files in the published output.
- Write alt text describing visible content without guessing identities, emotions, or sensitive attributes.

## Missing assets

Generate the site with the built-in neutral placeholder and clearly tell the user which slots remain incomplete. Never use reference-project portraits as placeholders.
The empty gallery also renders three neutral preview slots with an explicit “photos pending” note; it must not become an unexplained blank page. They are preview assets, not real couple photos.
